# 相邻工作速览（这套设计站在谁的肩膀上）

> 目的：把 local-superagent 的每个设计决定，对到已有论文的哪一条结论上；同时说清哪些东西**不是**我们发明的。
> 标注规则：`[已核对]` = arXiv 编号经检索确认；`[未核对编号]` = 只确认标题与作者，未逐条核对编号。

## 1. 一句话定位

本仓库做的是**工程装配**：把「推理-行动循环」「反思记忆」「多智能体分工」「显式工具调用」这些已有结论，装进一个能常驻、能并发、能自恢复、有人工闸门的运行时。它不提出新算法，也不主张新的模型能力。

## 2. 逐个对账

| 工作 | 编号 | 它说了什么 | 本仓库借了什么 | 没借 / 不同 |
| --- | --- | --- | --- | --- |
| **ReAct**：Synergizing Reasoning and Acting | arXiv:2210.03629 `[已核对]` | 让模型交替输出「思考」与「动作」，用环境观测纠偏 | worker 的每一步都是 `{"thought","tool","args"}` 或 `{"final"}`，工具结果回灌下一步 | 我们没有做它的 few-shot 轨迹设计；提示词是自拟的短规则 |
| **Reflexion**：Verbal Reinforcement Learning | arXiv:2303.11366 `[已核对]` | 失败后用语言反思写进记忆，下轮改进，不更新权重 | watchdog 判定 `stalled/loop` 后重启并保留会话上下文；worker 能看到 `ALREADY DONE THIS RUN` | 没有独立的「反思回合」；重启即纠正，靠规则不靠自我批评 |
| **Voyager**：开放世界具身智能体 | arXiv:2305.16291 `[已核对]` | 技能库 + 自动课程 + 迭代提示，在 Minecraft 里持续变强 | 「工单产出交付物 → 交付物成为下一轮输入」的结构；技能/工具白名单 | 没有技能库检索、没有课程生成；工单来自外部事件而非自生成目标 |
| **Toolformer**：模型自学用工具 | arXiv:2302.04761 `[已核对]` | 自监督地学会何时调用哪个 API | 工具以显式 JSON 协议暴露，而不是自由文本 | 我们不训练模型；工具选择完全由提示词 + 白名单约束 |
| **Generative Agents**：交互式社会模拟 | arXiv:2304.03442 `[已核对]` | memory stream + reflection + planning 三层 | 上下文当缓存：Inline & Spill（超阈值落盘、留续读句柄）+ 链式召回（message→thread→session→task） | 没有 embedding 检索与重要性打分；召回是显式 ID 链，不是语义搜索 |
| **AutoGen**：多智能体对话框架 | arXiv:2308.08155 `[已核对]` | 可对话 agent 之间用消息协作，支持人参与回路 | Router/Worker 分层 + 人只在该决策时被叫醒（panel 的 pending） | 没有自由的多 agent 群聊；角色是固定的两类，通信走结构化 Report |
| **MetaGPT**：把 SOP 编码进多智能体 | arXiv:2308.00352 `[已核对]` | 用标准作业程序约束角色，产出结构化中间物（需求/设计/代码） | 授权模型（Mandate/Policy）+ 工单状态机，把「谁能让它干活、能干多远」写成规则 | 没有角色流水线（PM/架构/工程）；我们的 Worker 是单一执行者 |
| **CoALA**：语言智能体的认知架构 | arXiv:2309.02427 `[已核对]` | 用记忆模块（工作/情景/语义/程序）与动作空间统一描述 agent | 领域模型里的 Thread/Ticket/Session 对应「情景记忆」，Policy/Mandate 对应「程序记忆」 | 我们没有实现完整的四类记忆；语义记忆缺失（没有向量库） |
| **AgentBench**：把 LLM 当 agent 评测 | arXiv:2308.03688 `[已核对]` | 多环境基准，暴露「会聊天 ≠ 会做事」 | 我们的验收也是任务级：267 条探针，而不是只看对话质量 | 没有接入标准 benchmark；负载是自造的合成场景 |
| **CAMEL**：角色扮演式 agent 协作 | arXiv:2303.17760 `[已核对]` | 两个 agent 用角色设定互相驱动完成任务 | 「主会话只分诊、执行者只干活」的职责切分 | 没有角色扮演对话；不追求自主协商 |
| Self-Refine / Tree of Thoughts（标题已确认，编号未核对） | — | 迭代自我改进 / 显式搜索多分支 | 只在「失败重试 + 换方法」这一层借鉴 | 没有实现搜索树，也没有多轮自我批评预算 |

## 3. 这套系统里真正「非论文」的部分

下面这些不是从论文里抄的，是工程约束逼出来的，也是这个仓库相对论文最有价值的部分：

1. **订阅直通**：Worker 直接订阅 thread，后续评论绕过 Router。省的是 Router 决策数与读缓存 token（实测决策 −30%、token −37%），不是时延。论文里没有这个机制，它来自「多会话并发时 Router 成为瓶颈」的工程观察。
2. **授权与路由分离**：Mandate 记录「凭什么做、能做多远」，Subscription 只负责「消息送到哪」。这解决了「看起来相关就被拉进执行」的越权风险。
3. **重复调用闸门**：真模型会原地打转（同参数连读同一文件 4 次）。这是纯工程问题，论文的 ReAct 循环里没有对应的防护。
4. **进程外看门狗**：进程内 watchdog 管不了整进程卡死；外部探活 + 重启预算（每小时 3 次）是运维约束，不是认知架构。
5. **注意力预算**：把「消息、通知、提问、面板元素」都按人的注意力计价，健康时保持沉默。这条来自产品判断，不来自任何论文。

## 4. 怎么用这份清单

- 想改**单步推理质量** → 回到 ReAct / Self-Refine，改 worker 提示词与工具设计。
- 想改**长期记忆** → 回到 Generative Agents / CoALA，补 embedding 检索与重要性打分（当前是显式 ID 链）。
- 想改**多角色协作** → 回到 MetaGPT / AutoGen / CAMEL，但那意味着放弃「单一执行者 + 单一授权」的简单性，要先想清楚谁负责验收。
- 想改**吞吐** → 不是论文问题：当前瓶颈是 `router.tick()` 按 thread 串行决策（实测 cap=4 相对 cap=2 无收益）。

## 5. 边界声明

本清单只用于定位设计来源，不声称任何论文的方法在本仓库被完整实现。逐条「我们实现了什么」以 `docs/01`–`docs/09` 的实测记录为准。
